# Infinite Item Progression — SQL Scripts

All SQL scripts for the custom item progression system live here,
numbered in the order they should be applied.

## Run Order

| Script | Description | Depends On |
|--------|-------------|------------|
| `step00_progression_schema.sql` | Creates `dynamic_items`, `character_dynamic_items`, `progression_event_log`, `progression_config` tables | — |
| `step04_essence_currency_salvage.sql` | Essence currency tokens (IDs 200010/200011), `alternate_currency` registration, Salvage Satchel container (ID 200020) | step00 |
| `step05_consume_item_essence_aa.sql` | Consume Item (AA 32100) and Consume Essence (AA 32101) abilities | step04 |
| `step08_09_augments_vendors_merge.sql` | Weapon/stat/proc augments, vendors (NPCs 181200-181203), merge catalysts, Augment Forge container (ID 200510). **Generated by `tools/generate_augments.py`** | step04 |
| `step10_zone_augments_quests.sql` | Zone-specific augments (201000+), global loot tables, collection quests. **Generated by `tools/generate_zone_augs.py`** | step08_09 |
| `step11_infusion_pool_catalysts.sql` | Infusion Pool container (ID 200530), Infusion Catalysts I-V (IDs 200520-200524), Forgemaster vendor entries | step08_09 |

## How to Apply

```bash
# From repo root — applies one script at a time
python run_sql.py utils/sql/item_progression/step00_progression_schema.sql
python run_sql.py utils/sql/item_progression/step04_essence_currency_salvage.sql
# ...etc
```

After running SQL, restart `shared_memory` then `zone` to reload items/spells/AAs.

## Notes

- Steps 1-3 are code-only (no SQL needed).
- Steps 6-7 are code-only (item scaling, custom stats).
- Step 8 and Step 9 are combined into one script because Step 9 (merge system) depends on the same augment/vendor data.
- Scripts use `ON DUPLICATE KEY UPDATE` or `REPLACE INTO` for idempotency — safe to re-run.
- All custom item IDs live in the 200000-210999 range to avoid PEQ database collisions.
